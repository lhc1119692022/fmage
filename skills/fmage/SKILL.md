# Fmage

- Reply in Chinese unless asked otherwise; this applies only to user-facing prose, not tool argument content. Keep provider names, model IDs, JSON keys, URLs, env vars, and paths unchanged.
- Use Fmage MCP tools, not scripts. Choose `generate_image` or `edit_image` for one request and the matching batch tool for multiple independent requests. Provider `transport`, `transport_profile`, and `prompt_profile` routing is automatic after provider selection; do not look for provider-specific image-tool variants. Call the selected base tool directly without enumerating or rediscovering tools; discover only when an expected Fmage tool is unavailable.
- Keep normal Fmage work in the current task. Do not create subagents for prompt writing, translation, comparison, attachment inspection, image submission, or waiting. Put multiple independent image jobs into one Fmage batch call.
- When a provider configured with `prompt_profile: "dall-e3"` (normally named `DE3限制版-image-2`) is selected, first finish exactly the same complete unrestricted source prompt you would pass to the corresponding base Fmage tool. Treat that source as the quality artifact: do not shorten, summarize, pad, repeat, or change its language, detail, or length to satisfy provider policy. Do not impose a source character target or let provider limits influence source-prompt writing.
- Submit the finished source prompt unchanged to the selected base image tool. Do not pre-translate, compact, or otherwise adapt it merely because it may exceed the provider limit. For a provider explicitly configured with `prompt_profile: "dall-e3"`, never pass `provider_prompt` to the base image tool; the initial tool result determines whether adaptation is needed.
- If an initial image call returns `ready=false` and `provider_request_sent=false`, keep the staged source unchanged and use the same active Codex model in the next continuation to derive `provider_prompt`. For an English-dominant source, first create a complete meaning-for-meaning Chinese translation with every constraint preserved; do not summarize or compact that translation. Only if the complete Chinese translation itself still exceeds the limit may you compact it without losing meaning. Compare the transport candidate against the source for subject, count, composition, exact text, reference roles, edit invariants, camera, materials, lighting, style, and avoid constraints. Continue through `prepare_prompt_dalle3` with `prompt_session_id` plus `provider_prompt`; never resend `prompt`. When preparation returns `ready=true`, call the same base image tool with `prompt_check_id` and the original provider/image/output parameters only; never resend `prompt` or `provider_prompt`. Do not use a subagent or external model for this translation. For a batch, continue each blocked job independently. These preparation responses send no provider request, are not image retries, and require no user approval.
- For every provider without that prompt profile, keep the normal path to: select the base image tool, write the prompt, call it. Do not add a prompt optimizer, prompt-cache lookup, status/trace preflight, or other diagnostic call.
- Treat every failed or partial image call as terminal for the current attempt. Stop and report its error or warning. Do not retry the same provider, change parameters and retry, select another provider, or call status/discovery tools to find an alternative provider unless the user explicitly asks for or approves another image call. A prompt-profile result with `ready=false` and `provider_request_sent=false`, whether returned by its image tool or preparation tool, is not a failed or partial image call; continue its preparation loop without asking for approval. Fmage never performs provider failover, and Codex must not simulate failover around it.
- When a user attachment is already clearly visible and its role is unambiguous, pass its supplied path directly to `edit_image`; do not separately open, render, or inspect it first. Inspect only when the requested change depends on details not visible in the attachment preview or when the image role/content is ambiguous.
- After a successful image result, do not call `view_image` or another inspection tool unless the user explicitly requested visual QA or the requested result cannot be verified from the returned metadata.
- Waiting and provider polling are necessary. Let the image tool perform its internal wait. For an asynchronous return, keep exactly one waiter or status check active, use the longest practical wait window, and poll again only after that wait reports the task is still incomplete; never issue concurrent or duplicate status checks.
- Before the image call, use the active Codex model to turn the user's request into one complete provider-appropriate image prompt. Preserve the requested subject, count, composition, exact text, style, and reference-image intent; do not bind this step to a named Codex model. Put the completed prompt in `prompt`, with one complete prompt per batch job.
- Classify the generation or edit intent internally and emphasize its relevant constraints; do not pass the class as a tool parameter.
- For every input image, identify it by index and role in the prompt, such as `Image 1: edit target`, `Image 2: style reference`, `composition reference`, `subject reference`, `base scene`, `supporting insert`, or `character anchor`. Do not assume every input is an edit target. When an image is guidance only, state what may be borrowed and what subject, composition, background, or content must not be copied.
- For edits, explicitly state `change only X; keep Y unchanged` and repeat the critical invariants on every iteration. Lock all applicable identity, pose, geometry, proportions, framing, camera angle, untouched regions, edges, layout, typography, text, palette, and style. For compositing, name what moves from which image into which base image and require matched lighting, perspective, scale, shadows, and color temperature.
- Quote required in-image text verbatim, require no extra characters, and preserve typography, spacing, placement, and hierarchy when the task changes only text. For complex requests, use only the helpful labels from: `Use case`, `Primary request`, `Input images`, `Scene/backdrop`, `Subject`, `Style/medium`, `Composition/framing`, `Lighting/mood`, `Text (verbatim)`, `Change`, `Keep unchanged`, `Match`, and `Avoid`; omit unused labels.
- Separate delivery parameters from visual language. `quality` controls generation quality/cost/speed; it does not mean sketch, wireframe, placeholder, grayscale, or any other visual style. Keep the requested finished-art direction in the prompt even when `quality` is `low`.
- Omit `quality` so the plugin uses the model default: `high` for `gpt-image-2` series models and `medium` otherwise. When the current request explicitly selects a non-default quality/speed/cost tier, pass `quality_user_requested: true`. Never infer a tier from resolution alone or infer `high` from professional, final, retouch, color correction, or editing language.
- Explicit `草图质量`, draft quality, preview quality, or low quality selects `quality: low` and `quality_user_requested: true`; for draft/草图 quality also use `resolution: 1k` unless another resolution was requested. A resolution request alone never selects quality.
- Treat sketch, hand-drawn, wireframe, and low-fidelity as visual styles only when explicitly requested. Resolve ambiguous `草图` from context without injecting wireframes, gray placeholders, or sketch styling; ask only when the distinction materially changes the result.
- Treat `占位素材`, `临时封面`, and `示意内容` as complete fictional but plausible content in the requested finished style, not empty boxes. Treat `效果图` as a coherent finished composition without decorative annotations or invented copy unless requested.
- Pass optional params only when specified or necessary; omit `provider` unless named and `output_dir` unless a save folder is specified. Named providers must be active and may be selected by their full name or a unique `active_providers` shorthand.
- Treat `1k`, `2k`, `3k`, and `4k` as resolution tiers, not fixed edge lengths. The selected transport resolves the tier and aspect ratio to the actual request dimensions; `requested_size` is authoritative. When saved image dimensions equal `requested_size` and there is no size warning, report normal success. Never compare a tier result with `4096x4096`, call it undersized/nonstandard/provider-capped, or offer a stricter retry unless the user explicitly requested an exact `WIDTHxHEIGHT`.
- `gpt-image-2` series models default to `quality: high` and the `4k` resolution tier. Preserve any explicit user-selected size, resolution, or quality tier.
- Completed output is compact and path-based. Use `display_images` for inline Markdown, for example `![Generated image](C:/Users/name/.codex/fmage/outputs/provider/run/image_1.png)`. No backslashes or `file://`.
- Final responses for completed images: prompt summary, provider/model, saved path(s), dimensions, manifest path, and inline images. Do not add a warning line when there is no blocking error. Mention a size mismatch only when the actual dimensions differ from `requested_size` or the plugin returns a size warning.
- For provider/config questions, setup, dry runs, trace/verbose output, failed/partial requests, or unusual async diagnosis, read [diagnostics.md](references/diagnostics.md) before acting. Normal generation, editing, and ordinary async waiting use the rules above without loading another reference.
