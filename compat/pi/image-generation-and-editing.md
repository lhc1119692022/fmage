## Image Generation And Editing

- When the user explicitly asks for `Fmage 图片退步`, the fixed local 1K/blur/noise recipe, or invokes `/skill:fmage-image-regression`, load `fmage-image-regression` and run its bundled skill script exactly once. This is the default fast path and intentionally bypasses Pi MCP Adapter. Do not also load or call the main `fmage` generation/editing workflow for that request.
- For raster image generation, image editing, color correction, color optimization, retouching, background changes, style transfer, or any other task that produces or edits an image, use the Fmage plugin.
- Load and follow the `fmage` skill (`/skill:fmage`), then call Fmage through Pi MCP Adapter's `mcp` bridge. Use the exact full base tool name exposed by the gateway, such as `Fmage_generate_image`, `Fmage_edit_image`, `Fmage_generate_image_batch`, or `Fmage_edit_image_batch`; provider and prompt-profile routing happens inside those base tools. Do not look for provider-specific image-tool variants, use Codex-style `mcp__Fmage.*` names, or use unprefixed logical names.
- When the user explicitly requests any quality tier, including `medium`, always pass that exact `quality`; omit it only when the user did not select a tier. If the selected tier differs from the model default, also pass `quality_user_requested: true`.
- After any Fmage image call fails or returns partial results, stop and report the failure. Do not retry, change parameters, query providers to find an alternative, or switch providers unless the user explicitly asks or approves it.
- Treat Fmage `1k`/`2k`/`3k`/`4k` values as resolution tiers. The selected transport's normalized `requested_size` is authoritative; when actual dimensions match it and no size warning is present, do not describe the output as undersized or compare it with `4096x4096`.
